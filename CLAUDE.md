# MarketPriceMonitor — CLAUDE.md

## Что это

Telegram-бот слежения за ценами на маркетплейсах (Python 3.14, aiogram 3, async
SQLAlchemy 2, Playwright): подключаемые провайдеры за планировщиком опроса с
контролем здоровья. Работают два провайдера — Ozon и Wildberries. Я им
пользуюсь сам, на десктопе с установленным Chrome.

## Главное, что нужно знать про этот проект

**Скрейпинг здесь работает только в одной конфигурации, и это проверено, а не
предположено:** настоящий Google Chrome (`channel='chrome'`), с окном (не
headless), с постоянным профилем. Бандленный Chromium из Playwright оба
маркетплейса отбивают всегда — и headless, и headed. Прямой HTTP к их
внутренним JSON API отдаёт 403.

Отсюда следствия, которые нельзя «оптимизировать» не подумав:

- `HEADLESS_ENABLED=false` и `BROWSER_CHANNEL=chrome` — рабочие значения, а не
  забытые дефолты.
- Контейнер парсить не может и не должен претендовать, что может.
- `MIN_REQUEST_INTERVAL_SECONDS` — не вежливость, а условие работоспособности:
  Ozon эскалирует защиту и после серии автоматических заходов с одного адреса
  начинает отдавать капчу даже ранее доверенному профилю.

## Принципы (держаться)

- Флагманское качество: чистая архитектура, тесты вместе с кодом, работающий CI,
  конфиг через env, структурный лог.
- **Заявления в README должны быть проверяемы.** Если написано «работает» —
  значит это запускали. Фейковый config-via-env, мёртвый код и команды-заглушки,
  которые рапортуют об успехе, — то, из-за чего этот репозиторий пришлось
  переделывать; не возвращать.
- Провайдеров добавлять только рабочих. Зарегистрированная заглушка = бот
  обещает маркетплейс и падает на нём.
- Public-safe: секретов нет, `.env.example` с плейсхолдерами, gitleaks-clean.

## Как запускать / тестировать

```bash
poetry install
poetry run alembic upgrade head
poetry run market-price-monitor            # бот целиком (нужен BOT_TOKEN)
poetry run market-price-check <url>        # проверить, что провайдер ещё жив

poetry run pytest -q                       # тесты: sqlite в памяти, без сети
poetry run ruff check . && poetry run ruff format --check .
docker compose --profile test run --rm tests

# миграции против настоящего Postgres + сверка схемы с моделями (это же гоняет CI)
DATABASE_URL=postgresql+asyncpg://... python scripts/check_schema_drift.py
```

Схема живёт в двух местах — в моделях и в миграции. Юнит-тесты строят её из
моделей на SQLite и по построению не видят расхождения с миграцией, поэтому
сверка идёт отдельным скриптом на настоящем Postgres. Правишь модель — правь
миграцию и прогоняй его.

Тесты не должны ходить в сеть и не должны зависеть от окружения разработчика —
за это отвечает автоиспользуемая фикстура `isolated_settings` в
`tests/conftest.py`. Живая проверка маркетплейсов — только через
`market-price-check`, руками.
